# LOW-008 PoC — word-import signs import time as PPXC.creationTime

Local-only, read-only reasoning PoC. No network, no infra, no secrets.

## Trace

1. `src/flows/identity/import.tsx:107-127` `importWords()`:
   ```ts
   entropy = createRecoveryWordCodec().recoveryWordsToEntropy(normalizedWords);
   const identity = await defaultCryptoProvider.deriveIdentity(entropy);
   complete(identity, pseudonym);   // no creationTime arg -> default
   ```

2. `src/flows/identity/import.tsx:83` default parameter:
   ```ts
   creationTime = BigInt(Math.floor(Date.now() / 1000))
   ```

3. `src/flows/identity/import.tsx:90-99` relabel + sign:
   ```ts
   const relabeledIdentity = { ...identity, pseudonym: normalizePseudonym(publicPseudonym), creationTime };
   const contact = defaultCryptoProvider.createPublicContact(relabeledIdentity, publicPseudonym, creationTime);
   ```
   `createPublicContact` (`src/protocol/ppxc.ts:59-97`) embeds `creationTime` into the unsigned contact body
   (`ppxc.ts:51`) and signs it (`ppxc.ts:72-75`). So the signed `PPXC.creationTime` == `Date.now()` at import.

4. Spec contract (`docs/security-architecture.md:393-403` + `:412-413`): the import time must be carried as
   `importedAt` local metadata, and "Never claim the import time is the original creation time."

5. `src/protocol/types.ts:281-291` defines `RecoveryWordsImportInput/Output` with `importedAt`, but a repo
   search shows those types are referenced only at their declaration — no flow/provider/worker uses them.

## Demonstrated drift

- Word-import path: signed `PPXC.creationTime` == import wall-clock time. Violates §12.
- PPXR/PPXV paths (`import.tsx:147`, `:159`, `:244`, `:256`): pass `recovery.creationTime` / `identity.creationTime` — correct, out of scope.
- `importedAt` local-metadata channel: declared, unimplemented.

## Impact

Signed-metadata authenticity only. `creationTime` is excluded from the fingerprint
(`docs/security-architecture.md:173`), so E2EE key binding is unaffected. No key recovery, no plaintext
leak. Same-fingerprint re-import silently refreshes a stored contact's signed `creationTime` via the merge
branch in `src/flows/contacts/manage.tsx:117-129`.

## Not a finding (verified sound, cross-cutting seams)

- QR MITM first-contact key swap: documented TOFU residual (`docs/threat-model.md`). Fingerprint IS
  displayable post-import in `src/components/cards/contact-management-card.tsx:41-46` (`<details>` full
  32-byte fingerprint) plus always-visible short identity ID — so the rubric's "no fingerprint to compare"
  condition is not met.
- Silent key-rotation overwrite: `src/app/contact-save-queue.ts:27-34` indexes by FULL 32-byte fingerprint
  (`contactStorageId`). A rotated key (different fingerprint) is added as a new record with a same-pseudonym
  collision warning (`src/flows/contacts/manage.tsx:131-143`), not an overwrite. The `update` mutation's
  `contact` patch only ever applies to a same-fingerprint record (same keys), so no key swap is possible.
- 20-byte `identityId` collision poisoning: sender lookup in `src/protocol/ppxq-inner.ts:103-106` and
  `src/flows/decrypt/sender.ts:7-14` is by full 32-byte fingerprint, not `identityId`. The 20-byte
  `identityId` is only used as `recipientId` compared against the active identity itself
  (`src/crypto/qr-text.ts:167`) and in recovery-practice verification (160-bit match, sufficient).
- Recovery-practice 4-word positions: `src/flows/identity/onboarding.ts:51-62` produces unique, sorted
  (stable) positions; `value % 24` modulo bias is negligible for a non-secret practice selector.
- Vault re-auth boundary: `PrivateExportCard` (`src/components/cards/private-export-card.tsx:57-68`)
  resets on visibility-hide and unmount; rendered only when identity is unlocked
  (`src/app/App.tsx:1160`); `lockActiveIdentity` (`src/app/App.tsx:170-177`) cancels decrypt, clears
  pending intent, zeroizes identity. Crafted incoming intent cannot decrypt against a wiped identity
  (App routes to "identity required" prompt, `src/app/App.tsx:869-899`).
