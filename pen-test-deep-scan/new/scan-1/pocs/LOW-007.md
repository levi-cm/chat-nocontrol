# PoC: LOW-007 — §16.2 `EncryptedTextObject` contract vs shipped v2 union

Non-harmful documentation/contract diff. No runtime exploit; demonstrates that the
§16.2 normative contract only describes v1 while the code ships a v1|v2 union.

## Normative `EncryptedTextObject` per `docs/security-architecture.md:§16.2` (lines 526-538)

```ts
export interface EncryptedTextObject {
  magic: 'PPXT';
  formatVersion: 0x01;   // <-- only v1
  suite: 0x01;
  flags: number;          // <-- unconstrained number
  mlKemCiphertext: Uint8Array; // 768 bytes
  ephemeralX25519PublicKey: Uint8Array; // 32 bytes
  salt: Uint8Array; // 32 bytes
  nonce: Uint8Array; // 12 bytes
  ciphertextLength: number;
  ciphertext: Uint8Array;
  checksum: Uint8Array; // 16 bytes
}
```

## Shipped `EncryptedTextObject` per `src/protocol/types.ts:132-145`

```ts
interface EncryptedTextObjectBase {
  magic: "PPXT";
  suite: 0x01;
  mlKemCiphertext: Uint8Array;
  ephemeralX25519PublicKey: Uint8Array;
  salt: Uint8Array;
  nonce: Uint8Array;
  ciphertextLength: number;
  ciphertext: Uint8Array;
  checksum: Uint8Array;
}

export type EncryptedTextObject = EncryptedTextObjectBase &
  ({ formatVersion: 0x01; flags: 0x00 } | { formatVersion: 0x02; flags: 0x01 });
```

## Drift

```
- formatVersion: 0x01            (single literal)
+ formatVersion: 0x01 | 0x02     (union, v2 added)

- flags: number                  (unconstrained)
+ flags: 0x00 | 0x01             (constrained per version)
```

## v2 emit / parse sites

- `src/crypto/text.ts:82-97` emits `{ formatVersion: 2, flags: 1 }` when gzip saves enough.
- `src/protocol/ppxt-outer.ts:15-24,93-105` accepts exactly `(v1,flags 0) | (v2,flags 1)`.

The v2 security behavior IS documented in `docs/protocol-v2.md` and summarized in
`docs/security-architecture.md:§10` (lines 294-301); only the §16.2 contract block is stale.
